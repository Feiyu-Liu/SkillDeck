## Implementation

T35 adds cookie-bound App sign-in attempts, authorization codes with 60-second expiry, S256 validation, atomic code/session exchange, replay revocation, rate limiting, and scheduled expiry cleanup. Migration `migrations/device-auth/0003_app_sign_in.sql` is required before deploying the new service. Existing Device Authorization remains available.

T36 adds `CloudWebAuthenticator` and `signInWithBrowser`. It reuses existing token/account finishing and secure-session semantics. Callback validation rejects the wrong scheme/path/state, authorities, fragments, duplicate parameters and missing codes before any exchange. Platform exceptions are reduced to the existing generic failure; the App shows the prescribed “other” failure text.

T37 uses `ASWebAuthenticationSession` with an ephemeral session and the existing NSWindow as its anchor. It adds no URL-scheme registration or entitlement. App code no longer uses Device Authorization or its browser-launch helper. The exact English/Chinese strings and existing Settings widgets are retained as the task specifies.

T38 compares Device-Bound sources by type and opaque source ID, leaving `==`/`hashCode` unchanged. The four Reconciler decisions are the synced short-circuit, generation-change decision, post-upload reread, and bootstrap matching. Source Epoch replacement detection remains independent. A real Workspace test verifies Mac rename, seed reload, publish and bootstrap; a read-only snapshot fixture covers declared-name/display fallback because Workspace intentionally disallows renaming through Draft publish.

T39 changes capture code and review artifacts only. It does not change any existing Cloud UI behavior or styling.
