  identifiers in `skills_workspace`. `RevisionId` is an opaque value type, and
  `RevisionObjectId` stays internal.
- **Reads stay reads:** export and import hold only the per-Skill read permit.
  Tests compare the database and WAL bytes before and after, and check that no
  Operation Record is added.
- **Import:**
  - the live Store is used only as a read-only alternate;
  - every object's raw content is validated;
  - the closure walk distinguishes incomplete from malformed;
  - publication is a single directory rename.
- **Migration:** the v3 to v4 migration rebuilds `skill_sources` with
  `TableMigration`. No other table references it, and the migration test runs
  `PRAGMA foreign_key_check`. The existing v2 test now runs the 2 to 4 path.
- **App changes:** the compatibility edits in `skilldeck-app` are the minimum
  that exhaustive matching on the sealed descriptor forces. They are recorded
  under Surprises in T03.

- **Size:** hand-written code is within twice the cards' estimates. About 4,500

## Items

### 1. Shared native pack builder changed for Recovery Bundles too

**Where:** `skills_workspace_revision_recovery_pack_create` in
`packages/skills_workspace/native/src/revision_engine.c`.

**What changed:**
- **Before:** the function inserted each retained root with
  `git_packbuilder_insert_recur`. In the pinned libgit2 that inserts the commit
  and its tree only, not its parents (`git_packbuilder_insert_commit` in
  `native/third_party/libgit2/src/libgit2/pack-objects.c`).
- **Now:** it walks all ancestry with `git_packbuilder_insert_walk`.

The export needed the walk. But this is also the production path for every
Revision Recovery Bundle, so the change reaches past T01's scope fence. The card
said to stop and ask before needing a different native behaviour.

**Why it matters:**
- **Bundle size and time:** every Recovery Bundle now carries full history,
  not just the retained roots.
- **Bundle creation can fail on Stores with ancestry holes:**
  - Retained roots are the before and after commits of the lineage's succeeded
    operations, plus the current heads (`_readPublishedRoots` in
    `drift_draft_update_state.dart`). Earlier Upstream commits, for example,
    are not roots.
  - Restore (`skills_workspace_revision_recovery_pack_restore`) checks only
    that the roots are readable commits.
  - So a Store restored from a bundle made before this change can lack
    non-root ancestors. With the walk, the next Bundle for that Skill fails
    with a bundle failure, and so does its export.

**Suggested change:** keep the recovery path exactly as it was, and give the
export the ancestry walk. Do this through a mode argument on the native call, or
a separate entry point. Add a test that a Recovery Bundle still contains only
the retained roots' objects.

**Decision (maintainer, 2026-11-24):** split the two paths. Recovery Bundles
go back to their earlier behaviour, and only export walks ancestry. The fix is
task card `../tasks/T05-m1-review-fixes.md`.

Export of a Store that already has holes will fail in either case. Add a typed
outcome for that, rather than a bare I/O failure.

### 2. Staged and temporary packs are never removed

**Where:** `revision_pack_import_command.dart`, `WorkspaceLayout.revisionPackStagingPath`,
and `destructive_recovery_entries.dart`.

- **Removing a Skill leaves its staged packs behind:** Removal deletes
  `<id>.git` but not `<compact-id>.packs`, so private Skill content stays on
  disk after the Skill is gone.
- **Crashed imports leave temporary directories:** an import interrupted by a
  process exit leaves a `.pack-*` directory in `revision-stores/`. Nothing
  removes it later.

**Suggested change:**
- Removal deletes the Skill's pack staging together with its Store, and is
  covered by the existing destructive recovery tests.
- Startup maintenance removes `.pack-*` directories that no operation owns.

Retention of successfully staged packs until M5 is fine and stays as recorded.

### 3. Synced Origin label validation rejects legitimate names

**Where:** `_requirePortableDisplayLabel` in `lib/src/domain/source_descriptor.dart`.

The labels reject `/`, `\`, `.`, `..`, and anything `Uri.tryParse` reads as
having a scheme, such as `notes:v2`. Folder names and device names can
legitimately contain these characters; for example, Finder allows `/` in names.
Such a Skill could then never be materialized on another Device, which would be
a status without a resolving action (R10).

This came from T03's acceptance line ("anything that looks like a path or URL is
rejected on decode"). That line was wrong. The type has no path or URL field,
so it is path-free by construction.

**Suggested change:** require labels to be non-empty after trimming, free of
control characters, and within a length cap, such as 256 characters. Keep the
exact-field check in the codec.

### 4. Export stages private content in the system temp directory

**Where:** `revision_pack_export_command.dart`, which calls
`Directory.systemTemp.createTemp`.

The full pack is written to the OS temp directory before being copied to the
destination. A process exit there leaves Skill content outside the Workspace,
where no Workspace cleanup can reach it.

**Suggested change:** stage under the Workspace layout, as import does. Item 2's
startup sweep should cover it too.

### 5. A failed Feed Check cannot carry `Retry-After`

**Where:** `FeedCheckResult` in
`packages/skills_cloud/lib/src/feed_check_scheduler.dart`.

`Retry-After` mostly arrives with 429 and 503 responses, which are failures.
T04's contract offered a delay only on success, so this is a card defect.

**Suggested change:** fix it in M3, when the HTTP client exists. Let a failure
carry an optional delay that takes precedence over the jittered backoff. No
change now.

### 6. Cloud CI is narrower than the CLI template

**Where:** `.github/workflows/skills-cloud-ci.yml`.

Compared with `skilldeck-cli-ci.yml`, two things are missing:
- **The `.github/**` path filter:** changes to `setup-ci` do not run Cloud CI.
- **The macOS runner on `main`:** Phase 1 is macOS first.

**Suggested change:** match the template's paths and runner matrix.
`workflow_policy_test.rb` needs its expectation updated with it.
